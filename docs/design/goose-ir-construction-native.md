# Goose IR construction native contract

This note records the construction-only wire operands and their lowering into the C backend. The complete semantic contract remains in [Goose IR specification §12.9](goose-ir-spec.md) and [§12.10](goose-ir-spec.md). Pilot and shrink records keep their existing encodings.

## High GIR destination records

All records below are selected only by `core-construction`. `val` operands name SSA values; `ty` is a type-table index; `org?` is the existing optional origin encoding.

| Record | Exact fields after the tag | Result and effect |
|---|---|---|
| `i_dest_publish_ref` | `val result, val built, org?` | Consumes a completed push destination, publishes its new element, and returns `ref mut E` to that element. |
| `i_dest_adapt` | `val result, val receiving_dest, ty producer_type, Request producer_request, org?` | Produces an adapted destination for a producer whose array-family representation or request differs from the receiver. It retains the original receiver metadata and storage. |
| `i_dest_adapt_finish` | `val result, val built_or_cancelled, org?` | Restores the saved receiving carrier type and request while preserving whether the producer completed or was cancelled. When the producer added an outer prefix absent from the receiver, lowering removes it in place and updates the stack top. |
| `x_dest_snapshot` | `val dest, val fixed_snapshot, org?` | Writes the already evaluated fixed-array elements in order. It emits element writes, not an ordinary storage-copy event. |
| `x_dest_repeat` | `val dest, val completed_source, org?` | Copies one completed fill value into each destination element, then consumes its private source. A construction trace records each copy with reason `repeat`. |
| `x_dest_copy` | `val dest, val source_ref_or_sampled_view, org?` | Samples and copies completed source storage once. A trace retains the source descriptor's storage and path. |
| `x_dest_publish` | `val built, org?` | Publishes a completed destination exactly once and updates its receiver's visible length or metadata. |

For a direct `CoreView::Of` length read, the high exporter evaluates the place once and emits `i_alen` on its reference when the pointee is `arr`, `grow`, `growshrink`, or `limited`. `varr` and other view expressions retain the `i_snap`/`i_vlen` path. This leaves the owner address available to the existing bounds-evidence matcher without changing sampled-view semantics.

## Low result descriptors

For `core-construction`, `gir-l/0.3` extends `lfunc` with one mandatory descriptor list between scopes and blocks:

```text
lfunc name [parameter_types] [] stack_count [members] [scope_parents] [lresult...] [blocks]
lresult_scalar source_type_key primitive_type output_parameter
lresult_snapshot source_type_key byte_extent output_parameter
lresult_reference source_type_key address_output_parameter
lresult_resizable_reference source_type_key header_output_parameter stack_output_parameter
lresult_slice source_type_key data_output_parameter count_output_parameter
lresult_nonfixed source_type_key request stack_parameter start_parameter count_parameter progress_parameter
```

Descriptor position is source result position. Output parameter positions form one ordered, distinct, consecutive suffix of the primitive function signature. Every named parameter is a pointer. Scalar descriptors name an integer or boolean primitive; snapshot extents are positive; reference outputs contain native pointers; slice counts and nonfixed counts are signed 64-bit integers. A nonfixed request is exactly `value` or `element_run`. Functions and global initializers with no results carry `[]`; omission is rejected. Pilot and shrink retain their previous seven-field `lfunc` records byte for byte. Construction uses `gir-l/0.3` and `gir-h/0.5` exclusively. Pilot and shrink remain on `gir-l/0.2` and `gir-h/0.4`; the older construction records are rejected.

A source type key is an opaque nonnegative module-local identity. Equal keys require equal physical descriptor kinds and layouts, independently of parameter positions and nonfixed request. Every member of one target must agree on result keys, descriptor kinds, layouts, and requests. The key preserves nominal distinctions within a checked low module; it does not prove that lowering faithfully translated the original source type. That is a separate translation obligation.

A nonfixed result has four pointer parameters: stack, saved start, count metadata, and progress. The count metadata remains exactly 16 bytes: count at offset zero and destination observation identity at offset eight, both signed 64-bit fields. Progress occupies a separate eight-byte cell. These parameters are scalar handoff mailboxes. Normal return writes count, identity, and Built progress into caller-owned storage; no pointer into the callee's frame escapes. A call's private input attempt and its output mailboxes are distinct objects. Nonzero return discriminants do not initialize normal result outputs.

Progress tags are Open=0, Suspended=1, Built=2, Published=3, Exiting=4, Abandoned=5, Cancelled=6, Attached=7, and Retired=8. Open with count zero differs from Built with count zero. Ordinary child creation suspends its parent; attachment marks the selected child Attached and reopens its parent before incrementing the parent's logical count. Finishing fixes the completed interval's endpoint and marks Built. Reading a completed attempt does not replace that endpoint with the current stack top.

Internal raw carriers contain five primitive words: stack, view start, attempt metadata pointer, attempt progress pointer, and a boolean mode relative to the current receiving activation. Every raw lease owns private metadata and progress cells. Its destination ID is historical observation data. A distinct graph-node pointer identifies the semantic attempt even when tracing is disabled and every observation ID is zero.

A receiving handle owns an exact incoming boundary, representation view, and current committed-successor lineage. Target receiving cells borrow the owning activation's controller. Descendant cancellation may change shared construction state but cannot consume or free that controller. It does not make an abandoned raw attempt writable. `DestRenew` resolves the receiving handle and begins a fresh attempt only when the selected attempt is terminal and resumable. `DestRefresh` consumes the previous writer and resolves it again after effects. Its result preserves the producer view while keeping the receiving prefix and rollback boundary separate. Raw historical carriers retain their original attempt identity.

Normal calls push a control shadow containing the callee ID and each nonfixed result's raw attempt, indexed by logical result position. Callee entry creates an activation-local receiving view whose boundary is exactly that raw attempt. For example, a helper called with pending replacement R2 stops normal landing at R2; sharing its graph with original channel R0 does not permit landing through R0. After normal return, the caller reconstructs its raw result with the same semantic attempt and original outward mode, compares stack, start, count, identity, and Built mailbox evidence, then pops the shadow. Escape edges recover cancellation carriers without reading uninitialized normal output mailboxes. Every normal or escape path balances its call shadow.

A callee starts with mode false relative to its own incoming outputs. Normal return restores the caller's mode. Reservation selection sets fresh mode relative to its receiving activation; escaping and forwarding preserve that payload mode. The boolean is an internal fifth word, never a fifth normal output parameter. Observation IDs never select cleanup, ancestry, renewal, or physical landing.

The verifier follows output addresses through frame addresses, constant offsets, block parameters, local members, and currently installed target cells. It checks each function's normal output writes and each call's output separation and incoming metadata. Call outputs become readable only on the corresponding zero-discriminant edge or after an actual covering write. A merge retains initialization only when every incoming path proves it. Unknown aliases do not prove initialization. While a call awaits dispatch of its return discriminant, only pure scalar/address computations and control flow may execute; effects and memory reads require the corresponding normal or target edge. Different pending calls cannot merge. Ordinary calls cannot resume while an escaped result is in flight; forwarding and receiving epilogues use the closed cleanup operations.

A member catch must transfer each exact escaped scalar, pointer, or count to its matching output channel. Loading or comparing a payload is insufficient. Complete snapshot copies retain byte provenance through aggregate frame staging. Later overlapping writes, including header writes, invalidate that transfer. Forwarding frames must retain the in-flight target discriminant and payload cells. Saved outer recursive cells and values retained across another call cannot stand in for the current payload. Reference source descriptors must follow their matching result channel. A forwarding `l_mark` retains the escaped end identity only while the tracked stack top is unchanged.

Nonfixed handlers reconstruct a raw lease from the receiving control's retained in-flight payload. Before adoption they independently compare its start, count, destination ID, replacement mode, Built progress, and current stack endpoint with the escaped scalar cells. `ExitAdopt` claims that exact handoff and creates a landing-only ticket. It does not reserve a new destination or emit a begin. An adopted ticket permits landing followed by release; discarding it is invalid. A moving landing also checks that the computed byte interval ends at the escaped endpoint before copying. These checks establish declared output initialization and exact payload transfer; they are not a general proof of arbitrary low pointer memory safety.

## Low target table and operations

The construction suffix of `gir-l/0.3` is a list of target tables:

```text
ltarget [member_function_ids] [cell_type_ids] [lchannel...]
lchannel result_position [incoming_cell_indices] [escaped_cell_indices]
```

`result_position` is the zero-based source result position. Channels appear in result order, so position `n` must equal channel index `n`; the verifier rejects negative, duplicate, missing, or reordered positions. Cell 0 is the boolean `active` flag. For each result in order, the table then allocates that result's incoming cells followed by its escaped cells. Every cell belongs to exactly one channel side.

For a fixed result, incoming cells are the addresses of its ordinary output words; escaped cells hold the corresponding primitive result words, or one pointer to the completed aggregate snapshot. For a nonfixed result, incoming cells are five pointers `(stack, saved_start, count_metadata, progress, receiving_control)` and escaped cells are `(value_start, value_end, i64_count, i64_destination_id, bool_replacement)`. These are cell indices, not byte offsets. The C emitter declares one typed thread-local C cell for each entry. The fifth incoming cell is target-only control state; it does not widen the normal four-pointer output ABI.

| Low record | Exact fields after the tag | Native effect |
|---|---|---|
| `l_rf_get` | `val result` | Reads the current thread's return discriminant. |
| `l_rf_set` | `val discriminant` | Stores zero for normal return or `target_id + 1` for a target return. |
| `l_target_load` | `val result, target_id, cell_index` | Loads the typed thread-local target cell. |
| `l_target_store` | `target_id, cell_index, val` | Stores the typed cell. Entry code saves prior cells, sets `active`, then installs incoming output pointers; exit code restores the saved cells. |
| `l_source_target_enter` | `val token, target_id, [optional_primitive_output_position]` | In trace mode, pushes the activation's result-source mapping. An empty position marks a non-reference result channel. |
| `l_source_target_result` | `target_id, result_position, val_source` | In trace mode, attaches a source descriptor to a returned reference channel. |
| `l_source_target_get` | `val result, val token, result_position` | In trace mode, reads the source descriptor captured for that activation. |
| `l_source_target_leave` | `val token` | In trace mode, pops that activation's provenance frame. |

Direct ordinary or target selection reuses an Open attempt with count zero, including when another lexical return ticket is live. It retains the incoming start, identity, and reserved prefix and emits no second begin. Named-result selection retains its direct path; its source snapshot is materialized only after every operand succeeds. If an operand interrupts a direct attempt after writing, cancellation abandons that attempt; the next resumed receiving use lazily begins a fresh attempt. Live tickets record lexical rollback scopes and do not create writer occupancy that forces replacement.

A named source carries its actual source binding, not a boolean permission to reuse the receiver. `ControlOwnerBind` binds a mutable named grow owner to its exact header, stack, and raw source node. `ControlNamedBind` retains an immutable named Built value's raw node, count, start, and end without granting mutation authority. Ordinary owners carry an explicit absent binding. Eligibility resolves the receiving side and compares that current node with the source binding's raw node. It never follows successors on a historical source value. `ExitIsNamed` exposes the selected ticket role: a different source takes the fresh construction/copy arm.

Named reservation begins in an awaiting-source state. At the source operand, `ExitMarkNamed` checks the actual source identity, count, and start and records a ready snapshot without abandoning a partial child. Only after every return operand succeeds does `ReservedNamed` materialize that snapshot. Interrupting a named reservation releases its ticket without discarding the named owner or its partial child. A successful materialization performs the required child cleanup and updates any receiving array-length prefix from the captured count before the ordinary bounded landing protocol. `ReservedNamed` carries its required materialization origin directly; prefix-capacity faults use the explicit return or whole implicit completion origin, independently of the leaf selection and source mark.

Implicit body completion creates a Waiting ticket for each nonfixed result before evaluating its completion expression. Waiting allocates scope authority without selecting an attempt, capturing a destination snapshot, or changing bytes. `ExitSelect` selects one existing fresh-or-named source on that same token at its actual leaf. Explicit return statements retain eager reservation before their first operand. A waiting ticket cannot supply a writer or named completion before selection.

Discarding a Waiting ticket transfers that exact token into one-use unselected-completion evidence for its own receiving authority. The matching receiving cancellation consumes the evidence without abandoning, truncating, or renewing the current attempt; an existing Built value retains its count and bytes. This cleanup exemption requires no live owned raw lease, delegation, or ordinary selection ticket. A live Built value requires the exact supersession authority described below. Escaped normal calls transport their actual consumed-Wait certificate through the checked result position in their call shadow, independently of whether the unchanged canonical attempt is Open or Built. Consuming that certificate performs no physical rollback; selected enclosing builders retain their own cleanup obligations.

A unique selected or received ticket can supersede a pending Waiting scope only for that same receiving view and activation, with its exact carried Built selection. This consumes the waiting evidence and performs ordinary protected cancellation; it does not create an unselected-completion certificate. Graph identity alone cannot establish supersession across normal-call views or foreign target controllers.

Direct multiresult producer calls own delegation aliases rather than construction guards. On escape they acknowledge their callee certificates and drop those aliases without inventing abandonment. A call inside a construction expression retains its actual builder guard and cancels it during unwind, even when the callee never selected that output. A callee's unselected certificate never grants a cleanup exemption to the caller's builder.

Terminal stop cleanup may release a Waiting ticket without selection or a cancellation witness. After that release, the checked path permits only more Waiting releases and the terminal stop. Ordinary return, escape, renewal, selection, and authority drops cannot use terminal release to bypass cleanup.

Mutable whole-owner references carry their optional binding as internal metadata through reference slots, block arguments, normal call shadows, and target return mappings. Primitive reference arguments and result words retain their existing ABI. `OwnerCheck` checks the raw source owner before a mutation; `OwnerUpdate` records the count and actual completed endpoint after the header and stack mutation. A source binding is not updated merely because its receiving graph has a successor. The stored endpoint avoids a return-time scan of nested named values. Binding tokens retain their raw source node and graph independently of receiving-handle drops; call and target shadows retain tokens across normal and escape teardown. Immutable named-value bindings cannot be used for owner mutation.

`ControlOwnerExtend` links a newly opened push, append, or whole-owner construction to its exact mutable binding. It snapshots the completed parent before suspending it. Cancelling the extension's receiving handle restores that completed prefix only after its selected child becomes terminal; cancelling an inner alias leaves the outer extension available to resume. Successful publication requires the exact completed extension before updating the parent's count and endpoint. Named materialization abandons the unfinished extension subtree and releases its physical rollback interval before restoring the completed parent.

Every exit ticket captures an immutable incoming boundary before chasing pending replacements. Cancellation protects explicitly carried raw attempts, abandons the remaining selected subtree, and restores the correct named or direct resumption snapshot. Cleanup resolves receiving handles without renewal. Landing stops at the ticket's committed boundary, performs protected cleanup first, and then moves at most one completed interval. Equal starts require no byte scan, move, or relocation event, including an empty completed original replaced at the same address. Different starts move the exact interval and emit one exit-value relocation. Release consumes the lexical ticket without fabricating storage effects.

Cleanup unwinds unrelated active local builders before cancelling the receiving boundary or discarding its enclosing tickets. A foreign target return releases its source ticket and drops its local borrowed authority before transferring the payload. Intermediate activations clean their own builders while forwarding; the owning target catches, adopts, cleans, and lands the payload. Value breaks and interrupted loop returns preserve this same inner-before-outer order. Escaping cancellation certificates are consumed through the attempt-cancellation operation, which owns their rollback and lifetime.

An escaping low call remains an ordinary `i_call`. It reads the return flag immediately afterward, branches on zero for normal output, and compares each statically possible `target_id + 1` before entering that target's handler. The verifier checks activation ownership, installed and restored cells, discriminant coverage, handler operations, and the unreachable invalid-tag sentinel before native emission.

## Native stack and provenance handling

Construction calls use a dynamic stack directory. `l_stack_at` resolves `(base, offset)` to a lazily created stable `gs_stack` cell, so recursive frames do not share the same stack object. Since recursive depth has no static bound, construction initializes the runtime's region-count cap to `GS_STACK_BUDGET / (GS_STACK_RESERVE + GS_STACK_GAP)`. Pilot and shrink continue to pass their statically counted region totals.

When no construction trace is requested, source-provenance operations have no native effect and trace IDs use zero. Trace-enabled emission retains descriptors across calls and target activations, recording storage identities and element paths without treating metadata pointers as program addresses. Destination events do not alter stdout or data layout.

## Control storage and lifetime

The closed `l_control_*` operation set is defined by `GirControlOf` and `GirControlOperands`; serialization, operand typing, low lowering, and C emission consume that shared description. It contains explicit scope, call shadow, receiving, attempt, reservation, landing, cancellation, and transfer operations. There is no string-selected runtime action or generic pointer call that substitutes for protocol authority.

Receiving handles, raw leases, tickets, and normal-call shadows retain graph nodes explicitly. Replacement-parent links are strong; expected-child links are weak. A weak thread-local list orders live attempts by creation independently of observation IDs. Protected abandonment scans that list newest first, follows immutable parent links, and skips explicitly carried subtrees; displaced children remain visible even when a replacement becomes the expected attempt. Freed nodes are unlinked immediately. A retained historical boundary keeps its committed successor alive. Renewal redirects predecessor links to the newest successor so repeated cancellation does not retain every intermediate attempt. Releasing the last handle, lease, ticket, or call reference reclaims its storage. Receiving cancellation retires that handle's consumed raw writer boxes while preserving explicit carried values, cancellation certificates, and other handles' parked writers. Metadata handed off from a returning helper is retained in this owned graph; it never points into a returned descendant frame.

`ReceivingDrop` is an explicit affine authority drop. It emits no event, abandons no destination, and changes no construction bytes. It requires no live or parked writer, delegation, or ticket in that local authority. A descendant activation may drop its borrowed target authority without closing the owning activation's controller; outer tickets do not belong to that local borrow. Completed raw leases retain their independent node and view references. Temporary completed aliases are dropped at their producer's handoff; scope exit releases remaining local storage after explicit semantic cleanup and does not invent abandonment events.

The representation adds heap allocations for control scopes, receiving handles, raw lease boxes, semantic attempts, lexical tickets, source bindings, and call/target shadows. Allocation depends on executed construction operations and is present without tracing. This note makes no allocation-rate, binary-size, or runtime-performance claim. Focused retry checks bound retained graph history; final compiler memory and performance gates remain separate requirements.

## Focused checks

The `compiler_gir` checks cover mandatory result descriptors, typed output positions and type identities, channel positions, activation and dispatch, exact payload transfer, endpoints, mailbox initialization, and receiving/ticket authority. `compiler_gir_reservations` retains Core fixtures for interrupted returns, named helper calls, owner extensions, cross-activation source bindings, and cleanup ordering. Each positive comparison requires independent Core acceptance. Its C emitter mode feeds Core/native comparison without relying on source forms rejected by the source exporter. `native_receiving_parity.py --emitter <compiled_fixture> --semantics <current_cli> --sanitize` validates and executes those same Core records before comparing native stdout, status, and events in both numeric profiles at O0/O2, with tracing enabled and disabled.

`native_receiving_lifetimes.c` exercises the actual emitted untraced runtime: historical raw identity, 1000 cancelled retries with bounded retained history, exact helper input boundaries, target payload lifetime across callee teardown, bounded borrowed-owner token retention, cancellation certificates that remain live after ticket discard, and repeated unselected completion across ordinary call shadows. Waiting guards reject duplicate selection, premature extraction, renewal or drop while waiting, mismatched carried evidence, and live Built leases without exact selected or received supersession. `native_receiving_lifetimes.py --emitter <compiled_fixture> --sanitize` generates that runtime and runs the invariants at O0/O2 in both numeric profiles. Sanitizer runs and exact event comparisons are execution checks of those cases, not a proof of arbitrary native control flow.
